# Benchmarks

See [methodology](../docs/phase4-benchmark-methodology.md) for exact build and run commands, verification, timing boundaries and limitations. The optional `chronos_bench` target uses Google Benchmark v1.8.3 pinned to a commit; `chronos_allocation_probe` separately counts a subset of C++ allocations. Neither is built by default. In reference mode, running the 10,000- and especially 100,000-order cases can be expensive because population repeatedly clones the book. Results are simulator-internal measurements, not network or production trading latency.

For Phase 4B comparisons, build both benchmark targets as described in the methodology, then run `bash benchmarks/run_comparison.sh path/to/new-output-directory`. It refuses to overwrite existing results. The script alternates planned and reference order by size, omits the reference 100,000-order cases, and runs allocation probes for each mode. Afterward summarize each mode's sample files with `benchmarks/summarize.py` and join the two summaries with `benchmarks/compare.py`; the [optimization report](../docs/phase4-optimization-report.md) gives interpretation and limitations. `CHRONOS_TRANSACTION_MODE=reference` selects the retained clone path for manual runs; `planned` is the default.
