# Phase 2 implementation report

## Overview and API

`chronos::orderbook::OrderBook` is an in-memory, single-threaded book for one `SymbolId`. `add(Order)`, `cancel(OrderId)`, and `modify(OrderId, price, quantity)` return explicit `Result` values. `find`, `best_bid`, `best_ask`, `level`, `depth`, and `orders_at` return value snapshots; `order_count`, `bid_levels`, and `ask_levels` report counts. `depth` is bounded and ordered best-first. `orders_at` exposes FIFO order in a copied vector. No internal iterator or reference escapes. Books are deliberately noncopyable and nonmovable because the index refers to owned nodes.

## Structure and complexity

Bids use a descending `std::map` and asks an ascending map. Each price level owns a FIFO `std::list` and a checked aggregate. An unordered index maps active IDs to their side, price, stable level address, and list iterator. The address is non-owning; level map nodes stay valid until the last order is removed, and the index entry is erased or redirected before that happens. Insertion and price-changing modifications take `O(log P)` for `P` levels plus expected `O(1)` ID work. Lookup and cancellation are expected `O(1)` aside from `O(log P)` removal of an empty level; hash lookups have linear worst case. Best price is `O(1)`; depth is `O(k)` for `k` returned levels, and copying a level's order snapshots is linear in that level's size. Space is `O(P + N)`.

## Priority, lifecycle, and invariants

Successful additions append to their price level. A same-price quantity reduction or no-op retains priority; an increase or any price change goes to the destination tail. Modifications keep ID, side, symbol, and original caller-supplied sequence metadata; their quantity is the new total resting quantity. FIFO uses call order, not sequence values or wall time. Deterministic replay therefore requires a caller to supply the same ordered operations. A cancelled ID may be reused immediately and is then a new arrival.

The core `Order` arrives as `New`; acceptance means it is resting by membership in the book, not by a new core status. Cancellation removes it and does not retain a `Cancelled` record. The book does not model partially filled or filled orders, retain an original quantity after amendments, or emit trades. A matching engine must later define fill transitions and sequence assignment explicitly; modification is not execution. Market orders cannot rest. A crossed book is allowed because this component does not match or enforce incoming-order policy.

Unique active IDs, correct side/symbol, positive price and quantity, per-level FIFO, exact aggregates, and no empty levels are maintained by validation and coordinated map/list/index updates. The existing `Order` constructor rejects malformed prices, zero quantity and invalid side/type before `add`; the book also validates reachable inputs and returns results for unsupported market orders, wrong symbols and duplicates. `modify` rejects nonpositive prices and zero quantities, and does not change symbol or side. `NotFound`, `DuplicateId`, `InvalidQuantity`, `InvalidPrice`, `WrongSymbol`, `InvalidModification`, `Overflow` and `UnsupportedOrderType` distinguish failures. Queries with an invalid side return empty results. External signed quantities must be validated before conversion to the unsigned type.

## Overflow and failure guarantees

Each level total is checked before addition, including modification of existing levels; side-wide totals are intentionally not provided, so totals across prices can exceed a `Quantity`. Reductions subtract only stored quantities from their own level, maintaining the aggregate invariant. An invalid operation or overflow leaves state unchanged. Allocation failures propagate standard exceptions: insertion rolls back a newly appended node and any new empty level if indexing fails, and a price change stages its destination before removing its source. The guarantee follows from these rollback paths and standard container guarantees; allocation-failure injection was not tested. No concurrency or reentrant callbacks are supported.

## Validation and limitations

The CTest suite contains 23 cases: eight foundation cases, eleven book cases, and four allocation-failure cases, including fixed-seed comparison against a simple reference model, FIFO, boundaries, overflow, snapshots and ID reuse. The final review's Debug, Release and ASan/UBSan builds each passed **23 of 23** cases (69 successful executions in the final matrix). The Debug CLI ran and formatting passed. GCC 13.3.0 and CMake 3.28.3 were used in WSL Ubuntu 24.04. An initial sanitizer run exposed a mismatch in the test harness's nothrow allocation override; correcting the harness resolved it. The Windows-mounted workspace previously produced intermittent Make clock-skew warnings. Windows Git's `diff --check` passed. Unconfigured WSL Git interpreted the pre-existing CRLF `.gitignore` and `LICENSE` as changed and reported whitespace; `git -c core.autocrlf=true diff --check` passed with the same line-ending policy as Windows Git. These checks exclude untracked files.

The allocation-failure regression executable injects `std::bad_alloc` at successive allocation points in insertion and price-changing modification, for new and existing destination levels. It checks that the original nodes, index and totals survive failures and remain usable. This covers those paths but does not prove every possible library failure, hash worst-case bounds, or future fill semantics. Phase 3 needs a best-resting-order snapshot and dedicated checked fill operation with identity protection against ID reuse, sequencing and event atomicity, market-order policy, risk checks, and matching rules; see the [proposed boundary](phase2-orderbook-design.md#proposed-phase-3-integration-boundary). Performance has not been benchmarked.
